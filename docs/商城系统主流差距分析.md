## 二、架构差距分析

### 2.1 多租户隔离缺口

```
当前架构：
  products (全局表，无 site_id)
  order_items (全局表，无 site_id)
  carts (全局表，无 site_id)
  coupons (全局表，无 site_id)

主流电商(SaaS模式)：
  site_1.products (逻辑隔离 or 物理隔离)
  site_2.products
  └── 每个站点有完全独立的商品池、订单流、定价
```

**影响：** 多站点部署时，A站点的商品会出现在B站点的商城中，订单归属混乱。

### 2.2 支付体系缺口

```
当前：支付仅 stubbed
  checkout → order created (status=pending)
  admin manually confirms (status=paid)

主流：
  checkout → payment gateway → async callback → auto confirm
  └── 微信/支付宝 native pay → 用户扫码 → 异步通知 → 自动status流转
```

### 2.3 订单状态机对比

```
当前状态流转：
  pending → paid → completed (manual)
  pending → cancelled
  paid → refunding → refunded

主流状态机（Shopify）：
  pending → authorized → captured/paid → fulfilled → completed
  pending → cancelled
  authorized → voided
  paid → refunded (partial/full)
  fulfilled → returned
  └── 每一步有事件、通知、日志
```

### 2.4 库存管理缺口

```
当前：
  下单时直接 stock = MAX(0, stock-qty)
  无预警、无锁定、无回滚

主流：
  下单锁定库存（15-30分钟）
  支付确认后扣减实际库存
  库存低于阈值触发通知
  支持预售/可超卖配置
```

## 三、可对齐部分（分期实施建议）

### 一期：基础商业闭环（1-2周）

| 模块 | 具体任务 | 复杂度 |
|------|---------|--------|
| 支付集成 | 对接支付宝当面付/电脑网站支付 | 中 |

| 支付集成 | 支付异步通知 → 自动确认订单 | 中 |

| 会员 | 用户地址簿 CRUD | 低 |

## 四、本系统独特优势（无需对齐）

以下能力是主流电商系统**不具备或需要付费插件**的差异化优势，不应对齐：

1. **AI多智能体运营** — Agent Matrix 自动生成商品描述、优化标题、生成营销文案
2. **1688供应链对接** — Ali API + Laodeng Publish 实现一键选品→AI优化→发布
3. **建站+商城一体化** — 用户可同时管理CMS网站+商城，无需两个系统
4. **知识库RAG客服** — AI客服基于自有知识库回答商品/售后问题

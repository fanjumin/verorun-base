## 二、可视化拖拽建站 — 实施计划

### 方案选择（两个选项）

#### 选项A：轻量方案（推荐优先执行，2-3周）
**在现有CMS block系统上做可视化增强**，不引入新框架

| 子任务 | 内容 | 工期 |
|--------|------|------|
| A1 | block实时预览：admin后台 → iframe加载cms_page.html实时渲染当前页面 | 3天 |
| A2 | 拖拽排序：上下拖拽调整block的position值，requestAnimationFrame平滑过渡 | 5天 |
| A3 | 原地编辑：双击block标题/内容 → contenteditable → 自动保存 | 5天 |
| A4 | 新增block：从组件列表选择并插入到指定位置 | 3天 |
| A5 | 发布/回滚：保存为草稿/发布/回退到上一版本 | 2天 |
| **合计** | | **18-20工作日** |

**技术增量**：
- 新增 `admin/static/js/block-editor.js`（~1000行，独立文件）
- 新增 `admin/static/css/block-editor.css`（~200行）
- admin.html 加一个 `l_block_editor` 入口函数
- 后端：新增 `PUT /admin/cms/blocks/reorder` API（排序变更）
- 后端：新增 `GET /admin/cms/page-preview?page=home` API（返回iframe渲染的HTML）

**零影响范围**：不碰cms_posts/agent_matrix/auth/user逻辑/community/任何登录流程

#### 选项B：完整方案（商业化建站绕不开，Phase 1-4）
**GrapesJS 作为独立页面引入**，与admin.html零耦合

| 阶段 | 内容 | 工期 | 技术决策 |
|------|------|------|---------|
| Phase 1 | 基础设施：GrapesJS独立页面 + 后端CRUD + 7个基础组件 + 保存/发布 | 4-6周 | 新建builder.html，不碰admin.html |
| Phase 2 | 组件生态：30+组件 + 主题集成 + 属性面板 + 媒体库 | 2-3周 | 扩展component_library表 |
| Phase 3 | AI建站生成：Agent Matrix + LLM → 页面JSON → 画布渲染 | 3-4周 | 复用现有Agent Matrix接口 |
| Phase 4 | 响应式 + CDN + 自有域名 | 2-3周 | nginx配置自动生成 |

**架构隔离**：GrapesJS运行在独立 `/builder` 页面，通过独立JS文件加载，与admin.html零耦合。

## 五、风险与隔离策略

| 风险 | 等级 | 策略 |
|------|------|------|
| admin.html 行数过多 | 中 | 选项B将builder独立页面，选项A独立JS文件 |
| 新旧CMS双重维护 | 中 | 过渡期保留blocks的发布渠道，逐步迁移 |
| 拖拽引入JS错误影响admin | 低 | 选项A/B代码均隔离在独立文件，不侵入admin核心逻辑 |
| 现有bug修复受阻 | 低 | 拖拽代码不加到admin.html主文件，不影响原有流程 |

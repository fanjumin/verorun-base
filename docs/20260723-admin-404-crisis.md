## 现象

所有插件管理路由返回 404/500，非插件路由正常（登录页、文章管理、订阅管理、用户管理等 HTTP 200）。

受影响的路由清单：

- `/admin/ads` → **404**
- `/admin/sms/*` → **404**

## 根因

### 直接原因：服务器 `admin/app.py` 的 import 区域换行符丢失

服务器 `/home/easykai/easykai-workspace/easykai.cn/admin/app.py` 在第 28-34 行的 import 语句之间丢失了换行符，多个 import 被拼接为一行：

```
# 服务器上的损坏状态（awk 'NR>=28&&NR<=35' 输出）：
from routes.subscription import sub_bpfrom routes.cleaner_agent import cleaner_bp
from models.cms import init_cms_tablesfrom routes.douyin_miniprogram import douyin_mp_bp
from routes.shop_admin import shop_bp
from routes.subscription import sub_bpfrom routes.cleaner_agent import cleaner_bp
from routes.deployment_api import deploy_bp, init_deployment_tables
```

Python 解析到这些行时抛出 SyntaxError，被 `admin/app.py` 第 169-192 行的 `try/except` 捕获，导致：
- `plugin_bp` 未注册 → `/admin/plugins/list` 404
- `captcha_bp` 未注册 → 验证码不可用
- `pm.mount_all_routes()` 未执行 → 所有插件 Blueprint 未注册 → 所有插件路由 404

### 为什么部署前能用，部署后不能用（触发条件）

服务器 `admin/app.py` 的损坏在磁盘上已存在一段时间。部署前旧 gunicorn worker 进程使用的是 **Python 字节码缓存（`__pycache__/app.cpython-*.pyc`）**，来自文件损坏前的正确编译版本，因此运行正常。

今日 kill 旧进程后 systemd 自动重启，新 worker 启动时 Python 检测到源文件 `admin/app.py` 的 mtime 比缓存更新，重新编译源文件 → 发现损坏的 import 语句 → SyntaxError → PluginManager 初始化被跳过。**缓存的失效暴露了早已存在的磁盘文件损坏。**

### 损坏的起源（无法精确追溯）

- 本地 `admin/app.py` 从未损坏过（git 记录中始终保持正确格式）
- 损坏只存在于服务器端
- 上一轮会话（2026-07-22）已发现过同样的换行符丢失问题，当时声称"已用本地正确版本覆盖修复"，但该修复从未提交到 git
- 由于修复未经 git 追踪，无法确认当时的覆盖修复是否真正执行，也无法排除后续操作重新导致的损坏

## 修复方案

1. 用本地正确版本覆盖服务器 `admin/app.py`（`scp` 方式）
2. 重启 admin 服务
3. 验证插件路由恢复

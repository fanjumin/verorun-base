## 二、阿里巴巴开放平台集成方案（独立模块）

### 2.1 功能定位

**独立模块 `ali_api/`**，挂载到 Admin 管理后台 (端口 8084)，提供：

- 通过 1688 商品链接/ID 采集商品详情
- AI 标题生成（多版本可选）
- AI 文案重写（优化 SEO 和转化率）
- 一键发布到本地商城（生成 products 记录）
- 查询历史管理
- 完整风控体系

### 2.2 技术选型

| 项 | 选择 | 原因 |
|----|------|------|
| API 认证 | HMAC-SHA1 签名 | 阿里开放平台标准签名方式 |
| HTTP 客户端 | `requests` | 轻量、已安装 |
| 签名工具 | 自实现 | 避免引入阿里 SDK 的复杂依赖 |
| AI 引擎 | 复用 `agent_matrix/engine.py` | 已有 DashScope/DeepSeek 供应商支持 |
| 图片存储 | 本地 `platform/static/products/` | 与现有文件结构一致 |
| 速率控制 | 内存计数器 + 数据库持久化 | 轻量高效 |

### 2.4 阿里巴巴开放平台 API 调用

#### 2.4.1 调用的接口

| API 名称 | 功能 | 调用频率限制（官方） | 风控层限制（自定义） |
|----------|------|---------------------|---------------------|
| `alibaba.icbu.product.get` | 获取商品详情（国际站） | 100/分钟 | 20/分钟 |
| `alibaba.product.get` | 获取商品详情（1688 国内站） | 100/分钟 | 20/分钟 |
| `alibaba.icbu.product.search` | 搜索商品 | 50/分钟 | 10/分钟 |

> **说明**：阿里巴巴开放平台 API 分为国际站（icbu）和国内 1688 站两套，实际调哪个取决于 AppKey 的授权。需要先在开放平台后台确认已授权的 API 列表。

#### 2.4.2 签名算法（HMAC-SHA1）

```
签名步骤：
1. 将请求参数按 key 字母序排列
2. 拼接成 key1value1key2value2... 格式
3. 构造签名字符串：HTTP_METHOD + "&" + urlencode(PATH) + "&" + urlencode(PARAM_STRING)
4. 使用 HMAC-SHA1 生成签名：hash_hmac(AppSecret + "&", sign_string)
5. Base64 编码后写入 _aop_signature 参数
```

### 2.6 风控机制（重点）

#### 2.6.1 四层风控架构

```
┌─────────────────────────────────────────────────────────┐
│                   第一层：用户级限流                       │
│  - 单用户 10 次/分钟（调用层）                            │
│  - 单用户 200 次/天（数据库记录）                         │
│  - 超限自动拒绝，返回 429                                 │
├─────────────────────────────────────────────────────────┤
│                   第二层：全局并发控制                     │
│  - 全局最大 5 个并发 API 请求                             │
│  - 使用 threading.Semaphore 控制                         │
│  - 超时等待 30 秒后返回 503                               │
├─────────────────────────────────────────────────────────┤
│                   第三层：熔断保护                         │
│  - 滑动窗口监控最近 100 次调用                            │
│  - 失败率 > 30% → 自动熔断 5 分钟                        │
│  - 熔断期间所有请求返回缓存数据（如有）                    │
│  - 半开状态：每秒放行 1 个请求探测                       │
├─────────────────────────────────────────────────────────┤
│                   第四层：审计与告警                       │
│  - 每次 API 调用记录 ali_api_logs                        │
│  - 异常模式检测（单用户短时间大量失败）                   │
│  - 检测到异常 → 自动封禁用户 + 通知管理员                  │
└─────────────────────────────────────────────────────────┘
```

#### 2.6.2 限流具体参数

| 参数 | 值 | 说明 |
|------|-----|------|
| `PER_USER_MINUTE_CAP` | 10 | 每用户每分钟最大请求数 |
| `PER_USER_DAILY_CAP` | 200 | 每用户每日最大请求数 |
| `GLOBAL_CONCURRENT_MAX` | 5 | 全局并发请求上限 |
| `CIRCUIT_BREAKER_THRESHOLD` | 0.30 | 熔断阈值（失败率 30%） |
| `CIRCUIT_BREAKER_WINDOW` | 100 | 滑动窗口样本数 |
| `CIRCUIT_BREAKER_COOLDOWN` | 300 | 熔断冷却时间（5分钟） |
| `REQUEST_TIMEOUT` | 30 | 单次 API 调用超时（秒） |
| `RETRY_MAX` | 2 | 失败最大重试次数 |
| `RETRY_BACKOFF` | exponential | 重试退避策略（1s→2s） |

#### 2.6.3 数据缓存策略

| 缓存项 | TTL | 说明 |
|--------|-----|------|
| 商品详情 | 3600s (1h) | 同商品 ID 一小时内不重复查询 |
| 搜索结果 | 1800s (30min) | 同关键词 + 同页码 |
| AI 生成的标题 | 86400s (24h) | 同商品同一批标题不重新生成 |
| AI 重写的文案 | 86400s (24h) | 同商品不重复生成 |
| 签名时间戳 | 实时 | 不做缓存 |

#### 2.6.4 安全措施

| 措施 | 实现方式 |
|------|----------|
| API 密钥加密存储 | AppSecret 存储在 `system_config` 表，通过环境变量或配置读取 |
| 请求签名 | 每次调用均重新生成 HMAC-SHA1 签名 |
| 参数校验 | 商品 ID 格式校验（纯数字），URL 白名单域名校验 |
| 管理员权限 | 阿里 API 调用仅限管理员使用 |
| 日志脱敏 | request_params 中 AppSecret 替换为 `***` |
| SQL 注入防护 | 全部使用参数化查询 |

#### 3.1.3 商品 SKU/规格管理

**需求**：支持商品多规格（颜色、尺寸、套餐等），每个 SKU 独立定价和库存。

新增表：

```sql
CREATE TABLE IF NOT EXISTS product_skus (
    id              INTEGER PRIMARY KEY AUTOINCREMENT,
    product_id      INTEGER NOT NULL REFERENCES products(id),
    sku_code        TEXT DEFAULT '',            -- SKU 编码
    spec1_name      TEXT DEFAULT '',            -- 规格1名称（如"颜色"）
    spec1_value     TEXT DEFAULT '',            -- 规格1值（如"红色"）
    spec2_name      TEXT DEFAULT '',            -- 规格2名称（如"尺寸"）
    spec2_value     TEXT DEFAULT '',            -- 规格2值（如"XL"）
    price_offset    REAL DEFAULT 0,             -- 价格偏移（相对于商品基础价）
    stock           INTEGER DEFAULT 0,          -- 独立库存
    image_url       TEXT DEFAULT '',            -- SKU 图片
    is_active       INTEGER DEFAULT 1,
    created_at      TEXT DEFAULT (datetime('now','localtime'))
);

CREATE INDEX IF NOT EXISTS idx_skus_product ON product_skus(product_id);
CREATE UNIQUE INDEX IF NOT EXISTS idx_skus_unique ON product_skus(product_id, spec1_value, spec2_value);
```

## 六、风险与注意事项

### 6.1 阿里巴巴开放平台风险

| 风险 | 应对 |
|------|------|
| AppKey 未授权目标 API | 先确认开放平台后台已授权的 API 列表 |
| API 调用频率被官方限制 | 风控层设置低于官方限制的阈值 |
| API 返回数据不完整 | 降级处理，记录日志，显示"部分数据缺失" |
| AppKey 被官方封禁 | 多 AppKey 备份，异常检测自动暂停 |

### 6.2 技术风险

| 风险 | 应对 |
|------|------|
| AI 生成内容质量不稳定 | 支持手动编辑，可重新生成 |
| 数据库迁移失败 | 所有 ALTER TABLE 放在 try/except，不影响现有数据 |
| 支付回调丢失 | 定时任务轮询支付状态作为兜底 |

### 6.3 兼容性

- 所有新增表使用 `CREATE TABLE IF NOT EXISTS`，不影响已有表
- 所有新增字段使用 `ALTER TABLE IF NOT EXISTS` 或 try/except 包裹
- 现有功能（购物车、下单、优惠券）全部保留，不做破坏性修改
- 阿里模块作为独立蓝图注册，可随时启用/停用

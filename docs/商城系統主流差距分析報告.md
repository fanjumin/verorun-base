# 商城系統與主流電商平台差距分析報告（精準版）

> 對比對象：Shopify / WooCommerce / 有贊 / Shopline
> 資料來源：實際代碼審查結果（2026-06-22）

---

## 一、支付功能

### 支付寶 — 代碼完整但尚未真正運轉

| 檢查項 | 實際狀況 | 證據 |
|-------|---------|------|
| RSA2簽名演算法 | ✅ 已實現，使用 `cryptography` 庫 | `payment_service.py` 第87-98行 `_sign()` |
| 產生支付表單 | ✅ 可產出 Form Auto-Submit HTML | `payment_service.py` 第135-148行 |
| 通知回調處理 | ✅ 已寫好回調端點 + 簽名驗證 | `shop_public.py` 第628-642行 `api_pay_notify()` |
| 通知URL設定 | ⚠️ **有Bug：路徑不一致** | `payment_service.py` 第149行 `notify_url = notify_base + '/payment/shop/notify'` ❌ 但實際路由是 `/shop/api/pay/notify`。如果沒手動修正路徑，支付寶回調會404 |
| 管理後台確認支付 | ❌ **無「確認支付」按鈕** | `admin.html` 第2259-2283行訂單操作只顯示「發貨」「退款」「物流」，看不到待支付訂單的確認操作 |

**結論：** 填了 App ID + 私鑰，生成支付二維碼/跳轉的程式碼能用。但回調URL路徑有Bug，且管理員後台沒有任何標記已支付的入口（除非前端用戶點「開發模式確認支付」）。→ **屬於「半成品」狀態，修好回調路徑Bug後才能用。**

### 微信支付 — 商城訂單完全不能用

| 檢查項 | 實際狀況 |
|-------|---------|
| 商城訂單微信支付 | ❌ **不存在**。`shop_public.py` 的 `/shop/api/pay/<oid>` 只調用 `payment_service.py`，裡面只有支付寶 |
| 微信Native支付 | ✅ 存在但只服務於**訂閱系統**，在 `subscription/gateway/wechat.py` |
| 商城能否複用 | 可以，但需要開發，把 `wechat.py` 的 `call_native_pay()` 接到 `shop_public.py` 的支付流程裡 |

**結論：** 微信支付在商城這側完全空白。填了Key也沒用。

## 四、核心缺失功能清單

以下功能是主流電商標配但本系統完全沒有的：

### 🔴 高優先級（影響商業運轉）

1. **商品圖片上傳** — 後台只有URL輸入框，管理員無法在管理介面直接傳圖
2. **管理員確認支付** — 後台無「確認付款」按鈕，依賴前端用戶操作或Stub
3. **SKU/規格管理UI** — 後端API完整但管理後台沒任何操作介面
4. **微信支付（商城）** — 商城訂單完全不支援微信支付
5. **支付回調URL路徑Bug** — `payment_service.py` 寫的路徑與實際路由不符

### 🟡 中優先級（影響運營效率）

6. **分類管理UI** — categories表已有但後台沒管理介面
7. **用戶地址管理** — 無地址簿，下單無法選收貨地址
8. **商品評價/評分** — 無評價系統
9. **郵件/簡訊通知** — 訂單狀態變更無自動通知
10. **超時自動取消訂單** — 無定時任務

### 🟢 低優先級（錦上添花）

11. **店鋪裝修** — 無拖拽式佈局編輯器
12. **會員積分/等級** — 無積分體系
13. **秒殺/限時折扣** — 無行銷工具
14. **數據報表** — 無銷售統計圖表
15. **商品批量導入/導出** — 無CSV操作

## 五、本系統獨有優勢（主流電商沒有）

不應對齊的差異化能力：

1. **AI智能體** — Agent Matrix 自動生成商品描述、優化標題（Shopify需安裝第三方AI插件）
2. **1688供應鏈對接** — Ali API 一鍵採集商品到本地商城
3. **建站+商城一體化** — 同一後台管理CMS網站+商城
4. **雲服務自動開通** — 下單後自動調配雲伺服器
5. **RAG知識庫客服** — AI客服基於自有知識庫回答售前售後問題

## 六、總結

| 面向 | 一句話結論 |
|------|-----------|
| **支付** | 支付寶填Key能生成支付頁但回調有Bug，微信支付商城不可用 |
| **後台商品管理** | 能填商品資料但不能上傳圖片，有SKU/規格API但沒管理介面 |
| **後台訂單管理** | 能發貨退款查物流，但管理員沒法標記已支付 |
| **前端購物體驗** | 商品列表/詳情/購物車/訂單流程基本完整，算可用 |
| **最大斷層** | 管理員後台的UI遠遠落後於後端API的能力 |

## 一、当前商城功能分析

### 1.1 已有功能清单

| 模块 | 功能 | 状态 |
|------|------|------|
| **商品管理** | 商品CRUD、分类、上下架、排序 | ✅ 已实现 |
| **购物车** | 添加、更新、删除、查看 | ✅ 已实现 |
| **订单系统** | 下单、查询、取消、退款 | ✅ 已实现（测试模式） |
| **优惠券** | 固定金额/百分比、有效期、使用限制 | ✅ 已实现 |
| **购买记录** | 用户购买历史、订阅状态管理 | ✅ 已实现 |
| **前端展示** | 商品列表、详情页、分类筛选 | ✅ 已实现 |

### 1.2 当前数据模型

```
products (商品)
├── id, title, subtitle, product_type (vip/template/token/service/plugin)
├── category, price, original_price, stock, sales_count
├── thumbnail, description, features (JSON), ai_config (JSON)
└── sort_order, is_active, created_at, updated_at

carts (购物车)
├── user_id, product_id, quantity, created_at
└── UNIQUE(user_id, product_id)

order_items (订单)
├── order_id, user_id, product_id, product_title
├── quantity, unit_price, subtotal, coupon_id, discount
└── status (pending/paid/refunded), idempotency_key

coupons (优惠券)
├── code, name, coupon_type (fixed/percent), value
├── min_amount, usage_limit, used_count, expire_at
└── is_active

user_purchases (购买记录)
├── user_id, product_id, order_id
├── purchase_type (once/subscription), expire_at
└── status (active/expired/cancelled)
```

### 1.3 当前架构特点

**优势：**
- 数据库表设计完整，覆盖基本电商流程
- 服务端验证完善（价格防篡改、幂等性检查）
- 内存限流机制保护API安全
- 前端页面已实现（商城列表、详情、购物车、订单）

**不足：**
- 支付系统未集成（仅测试模式）
- 缺少商品SKU/规格管理
- 缺少订单支付状态流转
- 缺少库存预警机制
- 缺少数据分析报表
- 缺少物流管理
- 缺少会员积分系统
- 缺少营销活动（秒杀、拼团等）

## 三、阿里巴巴开放平台集成方案

### 3.1 功能定位

**独立模块** — `ali_api/`，基于阿里巴巴开放平台API获取商品信息，支持：
- 商品详情查询（标题、价格、图片、描述、规格）
- AI智能标题生成
- AI文案重写
- 一键发布到本地商城

**核心优势：**
- 使用官方API，数据合法合规
- 无需反爬，稳定性高
- 数据完整，包含SKU、规格、库存等信息

### 3.2 技术方案

#### 3.2.1 模块结构

```
ali_api/
├── __init__.py
├── app.py                # Flask服务入口
├── config.py             # 配置（开放平台密钥、风控参数）
├── routes.py             # API路由
├── api_client.py         # 阿里巴巴开放平台API客户端
├── ai_processor.py       # AI标题生成、文案重写
├── risk_control.py       # 风控模块
├── database.py           # 数据存储模型
└── templates/            # 管理界面
    └── ali_api.html
```

#### 3.2.2 核心功能

| 功能 | 描述 |
|------|------|
| **商品详情查询** | 通过商品ID或URL查询1688商品详情 |
| **批量查询** | 支持搜索关键词批量查询商品 |
| **AI标题生成** | 基于原标题生成多个优化版本（SEO优化） |
| **AI文案重写** | 重写商品描述，优化转化率和SEO |
| **图片下载** | 自动下载商品图片到本地存储 |
| **一键发布** | 将查询的商品一键发布到本地商城 |
| **查询历史** | 保存查询记录，支持追溯和管理 |

#### 3.2.3 开放平台API调用

| API接口 | 功能 | 调用频率限制 |
|---------|------|-------------|
| `alibaba.item.seller.get` | 获取商品详情 | 100次/分钟 |
| `alibaba.item.search` | 搜索商品 | 50次/分钟 |
| `alibaba.item.img.get` | 获取商品图片 | 200次/分钟 |
| `alibaba.item.sku.get` | 获取商品SKU | 100次/分钟 |

#### 3.2.4 数据模型

```
ali_api_items (API查询记录)
├── id, item_id (1688商品ID), url
├── status (pending/processing/done/failed)
├── original_title, original_price, original_images (JSON)
├── original_description, original_specs (JSON)
├── original_sku (JSON) — SKU规格信息
├── ai_title_options (JSON) — AI生成的多个标题选项
├── ai_description — AI重写后的描述
├── selected_title — 用户选择的标题
├── publish_status (draft/published/failed)
├── target_product_id — 发布到本地商城后的商品ID
├── error_msg — 错误信息
├── api_request_count — 本次查询消耗API次数
├── created_at, updated_at, processed_at
```

#### 3.2.5 API设计

| 端点 | 方法 | 功能 |
|------|------|------|
| `/ali-api/api/item` | POST | 查询单个商品 |
| `/ali-api/api/search` | POST | 搜索商品 |
| `/ali-api/api/ai-title` | POST | AI生成标题 |
| `/ali-api/api/ai-rewrite` | POST | AI重写文案 |
| `/ali-api/api/publish` | POST | 发布到商城 |
| `/ali-api/api/history` | GET | 查询历史列表 |
| `/ali-api/api/history/<id>` | GET | 查询详情 |
| `/ali-api/api/history/<id>` | DELETE | 删除记录 |
| `/ali-api/api/stats` | GET | API调用统计 |

#### 3.2.6 风控机制（重点）

**3.2.6.1 调用频率控制**

| 控制项 | 限制 | 说明 |
|--------|------|------|
| 单用户查询频率 | 10次/分钟 | 防止单个用户过度调用 |
| 单用户日查询上限 | 1000次/天 | 防止API密钥消耗过快 |
| 全局并发控制 | 10并发 | 防止瞬间请求过载 |
| 熔断机制 | 连续50次失败触发 | 保护API密钥不被封禁 |

**3.2.6.2 请求队列**

```
请求队列流程：
用户请求 → 频率检查 → 队列排队 → API调用 → 结果返回

队列特性：
- 先进先出（FIFO）
- 自动限流（每秒最多5次请求）
- 超时自动重试（最多3次）
- 失败自动降级（返回缓存数据）
```

**3.2.6.3 数据缓存**

| 缓存类型 | 缓存时间 | 说明 |
|----------|----------|------|
| 商品详情 | 1小时 | 避免重复查询相同商品 |
| 搜索结果 | 30分钟 | 避免频繁搜索相同关键词 |
| AI生成结果 | 24小时 | 避免重复生成相同内容 |

**3.2.6.4 异常监控**

| 监控项 | 告警阈值 | 处理方式 |
|--------|----------|----------|
| API调用失败率 | >5% | 自动暂停调用，通知管理员 |
| 单用户异常调用 | >100次/小时 | 自动封禁，人工审核 |
| 敏感词检测 | 命中敏感词 | 拒绝发布，记录日志 |
| API余额预警 | <1000次 | 通知管理员充值 |

**3.2.6.5 日志审计**

```
ali_api_logs (API调用日志)
├── id, user_id, item_id
├── api_name — 调用的API名称
├── request_params — 请求参数（脱敏）
├── response_status — 响应状态码
├── response_time — 响应时间(ms)
├── error_msg — 错误信息
├── cost_points — 消耗积分/次数
├── created_at
```

**3.2.6.6 安全措施**

| 措施 | 说明 |
|------|------|
| API密钥加密存储 | 使用环境变量或加密配置文件 |
| 请求签名验证 | 防止请求被篡改 |
| IP白名单 | 限制调用来源IP |
| 参数校验 | 防止SQL注入和XSS攻击 |
| 异常请求拦截 | 检测并拦截恶意请求 |

## 六、总结

### 6.1 当前商城功能评估

当前商城具备基础的商品管理、购物车、订单和优惠券功能，但缺少企业级商城必需的支付集成、SKU管理、订单状态流转等核心能力。整体定位为"轻量级商城雏形"，距离专业企业级商城还有较大差距。

### 6.2 阿里巴巴端口采集模块价值

该模块将为商家提供高效的商品数据获取能力，结合AI标题生成和文案重写，帮助商家快速上架商品并优化转化率，是提升商城运营效率的关键功能。

### 6.3 下一步建议

建议优先实施第一阶段核心功能，特别是支付系统集成和订单状态流转，这是商城从"测试版"走向"可用版"的关键。阿里巴巴端口采集模块作为独立功能，可并行开发，为商城提供内容供给能力。

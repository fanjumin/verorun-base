# 项目日常工作规则（project_rules.md）
## 0. 会话期间禁止修改铁律
- 在与用户的当前会话阶段，绝对不允许修改任何文件或代码。
- 只能进行分析、讨论、输出方案，等待用户明确说"可以执行"或"改吧"后才能动手。
- 违反此条视为严重错误。

## 1. 工作流程原则
- 收到需求后，必须**先输出详细方案和执行计划**，绝不在用户明确确认前进行任何代码修改或工具调用。
- 每次响应前，先总结当前已累积的需求。
- 计划必须包含：目标、变更文件列表、潜在风险、步骤顺序。
- 每次修改代码后，必须同步更新 `docs/` 下对应的模块文档，提交前检查无遗漏。

## 2. 错误处理规范
- 出现编译或运行错误时，**必须先在对话中分析根因**，说明原因和修复方案，得到我明确确认后才能修改代码。
- 禁止一报错就盲目修改。

## 3. Git 操作规范
- **变更前先提交**：在对任何文件做实质修改前，如果存在未提交更改，必须先 `git add` 和 `git commit`，然后再开始新改动。
- **小步提交**：每次完成一个逻辑独立的改动（不超过 3 个文件），主动提醒我审查并提交。如果连续工作超过 20 分钟没有提交，也主动提醒。
- **禁止自动回滚**：除非我明确说出“回滚”或“撤销”，否则禁止执行 git reset、git checkout --、git clean 等命令。
- **危险命令确认**：执行以下命令前，必须先说明意图并获得我明确同意：
  - git reset / git revert / git checkout --
  - git clean
  - 任何可能覆盖或删除未提交代码的操作

## 4. 通用约束
- 严格遵守项目现有框架、目录结构和技术约定，禁止擅自创建独立文件或独立数据库。
- 所有修改必须通过 Trae 正常编辑流程。
- 如果不确定是否符合规则，必须先询问我。
